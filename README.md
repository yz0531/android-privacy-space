# 隐私空间 v1.8.0

一个轻量的 Android 工作资料管理器，用于隐藏用户选中的应用。它不替换系统桌面、不常驻后台，也不需要 root 或恢复出厂设置。

这不是 Android 15 系统“私密空间”的复刻。程序会创建一个名为“隐私空间”的工作资料，并成为该资料的 Profile Owner；它只能管理隐私空间中的应用副本，不能直接隐藏主空间中的同名应用。

本仓库目前未附带开源许可证，默认保留所有权利。

## 能做什么

- 在主空间选择已有应用，通过系统确认将其放入隐私空间并自动隐藏。
- 从系统文件选择器选择一个完整的单 APK，安装到隐私空间并自动隐藏。
- 安装成功后，由用户决定是否删除主空间原副本。
- 从隐私空间把应用反向放回主空间，并可选择删除隐私空间原副本。
- 选择隐私空间内已有的非系统应用进行隐藏。
- 拨号暗码直接进入桌面式隐私首页，以应用图标网格展示已隐藏应用。
- 点击图标会临时恢复并打开应用，返回隐私首页或设置页后再次隐藏。
- 隐藏程序自身的主空间桌面入口，并通过可配置的拨号暗码打开隐私首页。
- 在隐私空间管理页内完整删除该工作资料及其中全部数据。
- 一次点击发起创建；完成 Android 系统确认后，自动监控“系统受理、资料创建、策略配置、管理连接”并进入管理页，收到管理页反向确认后才判定成功。
- 取消或失败后持续确认系统回滚；结果未知时不会自动重复创建，避免生成第二个半成品资料。
- 无后台 Service、网络权限或电话权限。

“隐藏”使用系统的 `DevicePolicyManager.setApplicationHidden()`。应用隐藏后不只是图标消失，它在该工作资料中也不可运行；通过本程序打开时会先被临时取消隐藏。

## 系统要求

- Android 10（API 29）或更高版本。
- 系统必须开放工作资料（Managed Profile）功能。
- 当前应为设备主用户，且设备上没有另一个占用该位置的工作资料。
- 定制系统可能保留相关 API，却移除了创建入口或限制跨资料安装；豆包手机等目标设备需要真机验证。

创建过程会进入 Android 自带的系统确认界面。本程序不会静默接管设备，也不需要恢复出厂设置。

创建请求会明确启用 Android 的平台离线配置路径。在 Android 13 及以上版本中，这会跳过不可用的 Device Policy Management role holder，避免因 Google 基础服务被系统关闭而直接显示“无法设置设备”。

Android 不向普通应用公开创建百分比。本程序显示的是可核验阶段：已启动系统流程、系统已受理、收到最终成功回执。若标准创建流程失败，Android 会自动删除刚创建的工作资料并释放其空间；如果厂商系统异常留下本程序无法访问的半成品，主空间中的普通应用没有强制删除用户资料的权限，程序会提示进入系统设置检查，必要时使用 ADB 清理。

## 首次设置

1. 在主空间安装并打开“隐私空间”。
2. 点击“创建并自动连接”，在 Android 系统页面确认创建工作资料。
3. 程序自动完成资料配置并进入隐私空间管理页，无需手动刷新或再次连接。
4. 返回主空间后，点击“选择主空间应用，放入隐私空间”，选择要隐藏的应用。
5. 也可以点击“选择 APK 文件，安装到隐私空间”，选择一个完整的 `.apk` 文件。
6. 按页面提示允许“隐私空间”安装应用，并在系统安装页面确认。
7. 安装完成后，程序会在隐私空间中自动隐藏该应用。
8. 根据需要保留或删除主空间原副本。
9. 先测试拨号暗码能够正常打开程序，再点击“隐藏桌面入口”。

如果“创建隐私空间”不可用，常见原因是系统关闭了工作资料功能、当前不是主用户，或设备已存在工作资料。

## 创建状态与失败回滚

主空间页面会持久记录并显示以下状态：

- “系统创建流程已启动”：已进入 Android 创建页面。
- “系统已受理”：同步检查通过，但还不能算最终成功。
- “Android 已完成创建”：平台成功回执已到达，正在建立跨资料管理连接。
- “创建成功”：隐私空间管理页已经实际启动，并向主空间返回就绪确认。
- “创建未完成，回滚已确认”：程序收到了与本次目标用户匹配的 Android 工作资料删除回执。
- “创建已取消，可以重新尝试”：用户或系统取消后，连续 30 秒未出现新资料，且系统持续允许创建；这是安全重试条件，不冒充删除回执。
- “此前检测到的隐私空间已不存在”：应用运行期间没有收到删除广播，但重新打开后连续确认系统用户列表中已无该资料，并且系统已恢复创建能力。
- “创建超时，结果未知”：超过 15 分钟仍无最终回执，需要检查系统设置是否有异常资料残留。

Android 没有向普通应用开放创建百分比或异步失败详情，因此程序显示阶段和可验证终态，不伪造百分比。点击“重新检测创建结果”会立即重新查询系统状态。

如果创建是由旧版程序发起，最终广播可能已在升级前错过。新版仍会检查隐私空间是否可用以及系统是否允许重新创建；若两项信息互相矛盾，会明确显示“无法确认”而不是猜测成功或失败。

Android 官方创建流程规定：创建失败时应删除刚创建的工作资料并恢复原状态。本程序成为 Profile Owner 后会进行有限次数的幂等初始化重试；仍无法完成关键配置时才请求删除该未完成资料。若厂商系统崩溃或违反该契约，留下尚未启用且本程序无法进入的半成品资料，主空间普通应用没有权限强制删除；此时使用页面中的“打开系统设置检查或清理残留”，必要时再通过 ADB 删除对应用户。

## 放入隐私空间

在主空间点击“选择主空间应用，放入隐私空间”，选择一个应用后会按以下顺序执行：

1. 程序切换到隐私空间的安装页面。
2. 如果尚未授权，Android 会要求为隐私空间中的本程序开启“允许此来源安装”。此授权按用户/资料分别管理，只用于安装你主动选择的应用；操作完成后可以在系统设置中撤销。
3. 程序打开 Android 系统安装确认页面，由用户确认把该应用安装到隐私空间。
4. 只有确认目标应用确实已安装成功后，程序才会尝试将隐私空间副本隐藏。
5. 安装并隐藏成功后，页面才会提供“删除主空间原副本（可选）”。选择删除还会打开独立的系统卸载确认页面。

因此，“安装到隐私空间”和“卸载主空间原副本”是两次分开的系统确认。可以取消任意一步；取消删除会保留两个空间的副本。安装失败、安装被取消或隐藏失败时，程序绝不会启动源应用删除流程。

## 放回主空间

在隐私空间点击“选择隐私空间应用，放回主空间”，或在已隐藏应用卡片中点击“放回主空间”，流程与放入时相反：

1. 在主空间按提示开启“允许此来源安装”（如果尚未授权）。
2. 在 Android 系统页面确认安装到主空间。
3. 确认安装成功后，可选择“删除隐私空间原副本（可选）”。
4. 只有再次通过系统卸载确认，隐私空间原副本及其数据才会被删除。

如果只想让应用重新出现在隐私空间中，而不是放回主空间，请使用“恢复显示”或“全部恢复显示”。

## 从 APK 文件安装

主空间页面的“选择 APK 文件，安装到隐私空间”支持一个完整的单 APK，流程如下：

1. 系统文件选择器返回只读 URI，程序先复制到主空间自己的私有缓存；其他普通应用不能直接读取该文件。
2. 程序用随机令牌和一次性只读 URI 授权，把文件交给隐私空间中的本程序。
3. 隐私空间完成独立私有副本后，会立刻反向通知主空间删除第一份临时文件。
4. 隐私空间使用自己的只读 URI 打开 Android 系统安装确认页，不会静默安装。
5. 安装成功、取消或失败后，隐私空间副本立即删除；成功时再验证应用并自动隐藏。

两侧在应用启动、用户解锁或进入相关页面时还会清理已经超过 6 小时的残留文件，用于处理进程被杀、系统安装器不返回结果或厂商跨资料回执异常。临时文件不会放到公共下载目录。当前不支持 `.apks`、`.xapk`、拆分 APK 或安装包集合；文件上限为 1 GiB。

如果从旧版本升级，请先打开一次隐私空间管理页，让程序刷新跨资料路由，然后再使用放入/放回功能。

## “放入/放回”的数据含义

底层操作是把设备上已有的应用安装包复制安装到另一个 Android 用户资料，不是迁移应用数据：

- 两边使用同一应用包，但各自拥有独立的数据目录。
- 登录状态、聊天记录、数据库、下载文件、密钥、缓存和应用设置不会随安装迁移。
- 新空间里的应用通常会像首次安装一样，需要重新登录和配置。
- 删除某一空间的原副本，会永久删除该空间内的应用数据；另一空间的新副本不受影响。
- 如果需要保留数据，请先使用应用自身的同步、导出或备份功能。

## 安装兼容性与 ADB 备用方式

无 ADB 流程通过 Android 系统安装器的 `ACTION_INSTALL_PACKAGE` 配合 `package:<包名>` 请求安装另一资料中已存在的应用。AOSP/部分系统支持这种方式，但有些 OEM 安装器不处理 `package:` URI、禁止跨资料安装，或没有开放“允许此来源安装”页面。

遇到系统提示不支持、安装页无法打开或安装后没有成功时，可使用 ADB 备用。先查询用户列表：

```bash
adb shell pm list users
```

输出中会出现类似内容：

```text
UserInfo{10:隐私空间:...}
```

其中 `10` 是示例工作资料 ID，必须替换为设备上实际显示的数字。把已安装在主空间的应用加入隐私空间：

```bash
adb shell cmd package install-existing --user 10 com.example.target
```

安装后打开隐私空间管理页，点击“选择要隐藏的应用”完成隐藏。反向安装回主空间可执行：

```bash
adb shell cmd package install-existing --user 0 com.example.target
```

`com.example.target` 要替换为真实包名。ADB 同样只复制安装应用，不迁移数据或登录状态。

## 拨号暗码

默认暗码为：

```text
*#*#83746291#*#*
```

在程序主空间页面可设置至少 1 位数字。实际输入格式始终是 `*#*#数字#*#*`；例如把暗码设为 `1`，需要在系统拨号器中输入 `*#*#1#*#*`。输入最后一个 `*` 后应自动打开，无需拨出电话。

暗码验证成功后会直接进入桌面式隐私首页，不展示管理设置。首页以图标网格显示当前已隐藏的应用；点击图标即可打开，右上角设置按钮用于进入原有隐私空间管理页。

普通应用不能可靠接收 `#数字#` 这种拨号内容，因为拨号器通常会把它当作 MMI/USSD 指令。要保持程序轻量且不申请电话权限，本项目使用 Android 提供的 Secret Code 标准格式，外层的 `*#*#` 和 `#*#*` 不能省略。

保存新暗码时，程序会自动恢复桌面入口，便于先验证新暗码。确认暗码有效后再隐藏入口。

暗码只是一种隐蔽入口，不是密码或强安全认证。部分厂商拨号器和第三方拨号器不会向普通应用发送 Secret Code 广播，必须在目标手机上实测。如果暗码无效，不要隐藏桌面入口。

## 使用限制

- 工作资料被暂停（Quiet Mode）时，其中的管理页和应用都不能启动。请先从快捷设置、工作应用开关或系统设置中重新开启工作资料。
- 打开已隐藏应用时，程序会临时取消隐藏；Android 没有可靠的普通应用回调来判断任意第三方应用何时退出，因此需要返回隐私首页或管理页才会自动重新隐藏。设备重启、用户解锁或程序更新时也会补做隐藏；也可在管理页手动点击“立即重新隐藏全部”。
- 设备重启、厂商省电策略、系统“强行停止”以及拨号器实现差异，都可能影响暗码入口；桌面入口是主要恢复通道。
- 应用仍可能出现在“设置 → 应用”、工作资料管理页面、ADB 查询结果或系统审计界面中。本项目隐藏的是日常桌面入口和工作资料内的可用状态，不提供反取证能力。
- 删除工作资料会连同其中所有应用及其工作资料数据一起删除。

## 恢复与卸载

### 恢复被隐藏的目标应用

如果只是取消隐藏，打开隐私空间管理页，使用单个应用的“恢复显示”或“全部恢复显示”；这不会复制或删除应用。若要把应用重新安装到主空间，请使用对应应用的“放回主空间”。

### 恢复本程序桌面入口

如果暗码不可用，可通过 ADB 恢复并启动入口：

```bash
adb shell pm enable --user 0 com.example.privateentry/.LauncherActivity
adb shell am start --user 0 -n com.example.privateentry/.LauncherActivity
```

### 删除隐私空间

打开隐私空间管理页，滚动到底部点击“永久删除整个隐私空间”，再通过两次确认即可删除。此操作会永久删除隐私空间中的所有应用、账号、文件和应用数据，但不会清除主空间，也不会恢复出厂设置。删除开始后不可撤销。

确认后管理页随工作资料一起消失属于正常现象。如果厂商系统拒绝执行，可改用下方的系统设置或 ADB 方法。若之前隐藏了本程序的主空间桌面入口，删除隐私空间后仍需通过拨号暗码或 ADB 恢复入口。

也可以在系统设置中使用“移除工作资料”或“删除工作资料”。菜单名称因厂商而异，通常位于“密码与账号”“账号”“工作资料”或“安全与隐私”中。

也可先用 `adb shell pm list users` 确认工作资料 ID，再执行：

```bash
adb shell pm remove-user 10
```

该命令会永久删除对应用户及其中的全部应用数据。务必核对 ID，不能照抄示例数字。删除工作资料后，可在主空间正常卸载“隐私空间”。

## 构建

项目使用 Android Gradle Plugin 8.10.1、Gradle 8.14.3、compileSdk 35 和 Java 17。工程未附带 Gradle Wrapper，可直接用 Android Studio 打开；若本机已安装 Gradle 8.14.3，也可运行：

```bash
gradle :app:assembleDebug
```

Gradle 默认输出为 `app/build/outputs/apk/debug/app-debug.apk`。源码目录不保留 APK；需要安装包时请在本地按需构建。
